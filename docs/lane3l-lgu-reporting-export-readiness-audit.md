# Lane 3-L — LGU Reporting / Export Readiness Audit

## Current Branch

- fix/operator-staff-membership-layer

This lane is audit/doctrine only.

No PDF generation.
No CSV generation.

## Required Reporting Architecture Before Export

Before creating export buttons, implement/report doctrine must define:

1. Report type enum
2. Report period start/end
3. Generated by user ID
4. Generated by role
5. Generated at timestamp
6. Source filters used
7. Jurisdiction scope
8. Report version
9. Report status
10. Export format
11. Immutable report generation audit log
12. Whether report is official or draft
13. Signature / attestation requirements
14. Data retention policy

## Recommended Next Build Lane

Lane 3-M — LGU Report Doctrine + Report Type Registry

Scope:

- create report type registry doctrine
- define official report field schemas
- classify each report as dashboard-only, draft-export, or official-report-ready
- no export buttons yet
- no PDF/CSV yet

## Hard Rules

1. Do not add export buttons before report type doctrine is locked.
2. Do not generate official DOT/LGU reports from dashboard-limited data.
3. Do not treat frontend-limited rows as reporting-complete.
4. Do not use Intelligence panel as official reporting source by itself.
5. Backend reporting endpoints must own official report generation.
6. Official exports must create report generation audit records.
7. Report outputs must distinguish draft vs official.
8. Keep Manifest Submissions as workbench, Intelligence as summary, Reporting as separate controlled layer.
